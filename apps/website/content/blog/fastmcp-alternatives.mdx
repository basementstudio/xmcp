[FastMCP for TypeScript](https://github.com/punkpeye/fastmcp) and [FastMCP for Python](https://gofastmcp.com/) are separate projects. This guide compares alternatives to the TypeScript package. Its current documentation includes authentication support; switching frameworks is a choice about architecture and workflow, not a requirement for adding auth.

## Choose the alternative around your project

| Your requirement                                               | Starting point                 |
| -------------------------------------------------------------- | ------------------------------ |
| Direct control of protocol registration and transport setup    | Official TypeScript SDK        |
| An HTTP endpoint inside an existing application                | mcp-handler or an xmcp adapter |
| File-based tools, prompts, and resources with a build workflow | xmcp                           |

The [official SDK](https://github.com/modelcontextprotocol/typescript-sdk) gives you direct access to MCP server and client APIs. Version 2 separates server and client packages. Check its migration guide before copying a version 1 example.

The [mcp-handler project](https://github.com/vercel-labs/mcp-handler) exposes a Fetch-compatible HTTP handler. It includes bearer-token authorization helpers; application-specific identity and access rules remain your responsibility.

## When xmcp fits

xmcp discovers tools from `src/tools/`, validates inputs using Zod, and builds HTTP or STDIO entrypoints. It also has [framework adapters](/docs/adapters/nextjs), so adopting it does not require creating a separate service.

Choose it when your team wants independently maintained tool files and a consistent build and deployment workflow. Start with a [template](/templates) and review the [integration catalog](/docs/integrations) for your identity, payment, or data provider.

## Plan a migration

Move one representative tool first. Preserve its name, input schema, result shape, authorization checks, and client configuration. Test it with the same client before moving the rest. Review transport semantics explicitly: a server that relies on in-memory sessions cannot be moved to stateless HTTP by changing imports alone.

Use the [TypeScript build guide](/blog/build-mcp-server-typescript) for the first tool and the [transport reference](/docs/configuration/transports) for deployment configuration. Keep the original server available until clients have been checked against the replacement.
