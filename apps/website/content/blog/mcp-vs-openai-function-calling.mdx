Both OpenAI function calling and the Model Context Protocol (MCP) let an AI model invoke external code. On the surface they look similar. The difference is what they're designed for — and that difference matters when you're deciding how to build.

## The short answer

|                           | OpenAI function calling                          | MCP                                              |
| ------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| Scope                     | OpenAI models only                               | Any MCP-compatible client                        |
| Where tools are defined   | In the API call payload                          | In a separate MCP server                         |
| Transport                 | Through the OpenAI API                           | STDIO or HTTP                                    |
| Integration               | Application using the OpenAI API                 | MCP-compatible applications and API integrations |
| Tool reuse across clients | Reuse implementation behind application adapters | Shared MCP interface                             |
| Standard                  | OpenAI-specific                                  | Open, multi-vendor                               |

## What OpenAI function calling is

OpenAI supports [function calling](https://developers.openai.com/api/docs/guides/function-calling) in its APIs, including Responses. The application supplies tool definitions, receives a requested call, executes its code, and returns the output. Exact request and response shapes depend on the API.

You can reuse that function implementation elsewhere; the provider-specific part is the adapter between the model API and your application. This is useful when your application already owns the tool execution loop.

## What MCP is

The [Model Context Protocol (MCP)](/blog/what-is-an-mcp-server) takes a different approach. Instead of embedding tool definitions inside API calls, you build a **separate server** that exposes tools (and resources and prompts) over a standardized protocol. Any MCP-compatible client can connect to that server and use those tools.

The tools live outside any particular model or API. Claude, Cursor, GitHub Copilot, and a growing list of clients all speak MCP. You expose one interface, then verify transport, authentication, and capability support in each target client.

## The key architectural difference

With function calling, the **client application** owns the tools. The model asks to call a function; the client runs it.

With MCP, the **MCP server** owns the tools. The AI client (Claude, Cursor, etc.) connects to your server and discovers what it can do. The server runs independently.

This separation is what makes MCP tools reusable across clients. If you want your tools to be available in Claude Desktop, Cursor, and whatever AI client your users prefer next year, MCP is the right abstraction. If you're building a tightly coupled product around the OpenAI API, function calling may be simpler.

## Can you use both?

Yes. The [OpenAI Responses API supports remote MCP tools](https://developers.openai.com/api/docs/guides/tools-connectors-mcp) alongside function tools. With a remote MCP tool, OpenAI connects to the server and returns MCP call results; with a function tool, your application executes the requested function. Configure authentication and approvals for the data and actions involved.

## Building MCP servers with xmcp

If you're building an MCP server in TypeScript, [xmcp](/docs) handles the protocol, transport, and tool discovery for you. You write a file per tool, and xmcp exposes it over MCP:

```typescript title="src/tools/search.ts"
import { z } from "zod";
import { type InferSchema } from "xmcp";

export const schema = {
  query: z.string().describe("The search query"),
};

export const metadata = {
  name: "search",
  description: "Search for information",
};

export default async function search({ query }: InferSchema<typeof schema>) {
  // your implementation
  return `Results for: ${query}`;
}
```

Any MCP client — not just one provider — can then use this tool.
