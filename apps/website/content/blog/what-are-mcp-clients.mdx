An [MCP server](/blog/what-is-an-mcp-server) exposes tools, resources, and prompts. An **MCP client** is the AI application that connects to it, discovers what's available, and lets the model call those tools. The two sides are defined by the same protocol, which means a server built once works with any compliant client.

Here's what the client ecosystem looks like in 2026.

## How clients connect

MCP clients connect to servers over one of two [transports](/blog/mcp-server-transports-explained):

- **STDIO** — the client launches the server as a child process and communicates over stdin/stdout. Used for local tools on the same machine.
- **Streamable HTTP** — the client connects to a URL over HTTP. Used for remote servers and multi-user deployments.

Each client has its own configuration format for adding MCP servers, but the connection model is the same.

## Claude Desktop

**Connection options:** local STDIO configuration, remote connectors, or a local HTTP bridge

Claude Desktop is Anthropic's native desktop client and has one of the earliest MCP integrations. You configure servers in its `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "my-server": {
      "command": "node",
      "args": ["/path/to/dist/stdio.js"]
    }
  }
}
```

A command-based local configuration can bridge to an HTTP server with `mcp-remote`:

```json
{
  "mcpServers": {
    "my-server": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://your-server.vercel.app/mcp"]
    }
  }
}
```

Claude also supports [custom remote MCP connectors](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp). Use that setup for hosted endpoints; it is separate from local command-based configuration.

## ChatGPT

**Connection options:** remote servers over streaming HTTP or SSE, added as a plugin on ChatGPT web, or private servers through Secure MCP Tunnel

ChatGPT connects to your server from OpenAI's infrastructure, so it cannot reach `localhost`. Give it a public HTTPS endpoint, including the `/mcp` path, or connect a private server through [Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels). To [add a server](https://developers.openai.com/api/docs/guides/developer-mode), open ChatGPT Plugins, select the plus button, then **Add custom MCP server**. Enter the URL, choose authentication, accept the risk warning, and select **Create as a plugin**. Install the plugin, then type `@` in the prompt box to use it.

What ChatGPT supports, according to OpenAI's documentation:

| Feature               | Support in ChatGPT                                                                                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tools                 | Read and write tools. Tools without the `readOnlyHint` annotation are treated as write actions and need confirmation by default.                                                                                                   |
| Resources             | Used for MCP Apps UI: a tool points to a UI resource with `_meta.ui.resourceUri`. OpenAI does not document other resource use.                                                                                                     |
| Prompts               | Not documented. OpenAI's [MCP server page](https://developers.openai.com/plugins/concepts/mcp-server) says plugins "primarily use tools."                                                                                          |
| Server `instructions` | Read from the server and refreshed with the tool list.                                                                                                                                                                             |
| MCP Apps UI           | Yes. ChatGPT [implements the open MCP Apps standard](https://developers.openai.com/plugins/build/chatgpt-ui) and renders UI in an iframe.                                                                                          |
| Transport             | Streaming HTTP and SSE, remote only.                                                                                                                                                                                               |
| Auth                  | OAuth (static client credentials, Client ID Metadata Documents, or Dynamic Client Registration), no authentication, or a mix where some tools need OAuth.                                                                          |
| Developer mode        | Not required. You don't need to turn it on first; you acknowledge a risk warning for each server you add.                                                                                                                          |
| Plans                 | [Full MCP](https://help.openai.com/en/articles/12584461-connecting-custom-mcp-servers-in-chatgpt) (read and write) on Business and Enterprise/Edu. Pro can connect servers with read/fetch permissions only. Web only, not mobile. |

So can a ChatGPT MCP connector use resources and prompts, or only tools? In practice, tools. ChatGPT reads UI resources for [MCP Apps](/blog/mcp-apps), but OpenAI doesn't document it reading other resources into the conversation or offering MCP prompts to users. If the model needs some data, return it from a tool.

When an admin publishes a custom server to a Business or Enterprise/Edu workspace, ChatGPT uses a frozen snapshot of its tools. Later changes to the server reach users only after an admin refreshes and republishes it. To publish a server in the ChatGPT directory, follow [How to submit your ChatGPT MCP app](/blog/build-and-submit-gpt-apps).

The ChatGPT desktop app works differently: it [shares MCP configuration](https://learn.chatgpt.com/docs/extend/mcp) with the Codex CLI and IDE extension, and can add local STDIO or Streamable HTTP servers under **Settings > MCP servers**. [MCP with OpenAI](/blog/mcp-with-openai) covers that setup and the Responses API.

## Cursor

**Transport support:** Streamable HTTP and STDIO

Cursor added MCP support in 2025 and treats it as a first-class feature. HTTP servers connect directly — no bridge needed:

```json
{
  "mcpServers": {
    "my-server": {
      "url": "https://your-server.vercel.app/mcp"
    }
  }
}
```

STDIO servers use the same `command` / `args` pattern as Claude Desktop. Cursor exposes connected tools inside the Composer and Chat interfaces, and the model can call them during normal coding sessions.

## GitHub Copilot

In VS Code, configure MCP servers through `mcp.json` or the **MCP: Add Server** command. STDIO and HTTP connections are supported. Follow the [VS Code MCP documentation](https://code.visualstudio.com/docs/agent-customization/mcp-servers); other Copilot surfaces have their own setup and capability limits.

## Windsurf

**Transport support:** STDIO and HTTP

Windsurf (by Codeium) is an AI-first IDE that supports MCP server connections through its cascade feature. Configuration is similar to Cursor — servers are declared in a settings file and become available during AI-assisted coding sessions.

## Other clients

The MCP ecosystem is growing quickly. Other clients with MCP support include:

- **Zed** — the collaborative code editor has MCP integration in its assistant.
- **Continue.dev** — the open-source AI coding assistant supports MCP for tool extension.
- **Custom agents** — any application built with the MCP TypeScript or Python SDK can act as a client.

## What this means for your server

MCP provides a shared protocol, but clients differ in supported transports, authorization flows, and optional capabilities. Test your tools with each target client instead of assuming identical behavior. Use the [connection reference](/docs/getting-started/connecting) and a [runnable template](/templates) to establish a working baseline.
